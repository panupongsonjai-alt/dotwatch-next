# ย้ายข้อมูลจากระบบเก่า

ใช้คำสั่งเดียว `npm run legacy:import` โดยสคริปต์จะ**อ่านระบบเก่าอย่างเดียว** แล้วเขียนลงระบบใหม่ รันซ้ำได้เสมอ
รอบหลังจะเพิ่มเฉพาะส่วนที่เปลี่ยน และถ้าหยุดกลางทางให้รันคำสั่งเดิมเพื่อทำต่อ

## 1. ไฟล์ตั้งค่า (ทำครั้งเดียว)

คัดลอก `services\api\.env.migrate.example` เป็น `services\api\.env.migrate` แล้วใส่ 4 ค่า:

| ค่า | เอามาจาก |
|---|---|
| `LEGACY_DATABASE_URL` | Render → **ฐานข้อมูล PostgreSQL ของระบบเก่า** → Connect → **External** Database URL |
| `LEGACY_SECRET_KEY` | Render → backend ระบบเก่า → Environment → `DEVICE_SECRET_ENCRYPTION_KEY` |
| `DATABASE_URL` | Render → `dotwatch-api` → Environment → `DATABASE_URL` |
| `DEVICE_SECRET_PEPPER` | Render → `dotwatch-api` → Environment → `DEVICE_SECRET_PEPPER` |

ไฟล์นี้ git จะไม่เก็บ และใช้กับการย้ายข้อมูลเท่านั้น งานพัฒนาปกติในเครื่องยังใช้ `.env` เหมือนเดิม

## 2. ทดลอง (ไม่เขียนอะไร)

```powershell
npm run legacy:import -- --dry-run
```

ตรวจบรรทัด `ไปที่:` ว่าเป็นฐาน production แล้วดูส่วนสรุปและข้อควรรู้ (บรรทัดที่ขึ้นต้นด้วย `!`)

## 3. ย้ายจริง 2 รอบ

```powershell
npm run legacy:import -- --yes
npm run legacy:import -- --yes
```

ทั้งสองรอบต้องจบด้วย `ตรวจยอดแถว: ตรงกันครบ ✅` รายงานอยู่ใน `_reports\` ถ้ามีอุปกรณ์ที่ได้รหัสลับใหม่
จะมีไฟล์ `new-device-secrets.csv` สำหรับใช้แฟลชบอร์ด ไฟล์นี้ห้ามส่งต่อ

## สิ่งที่ย้าย

ผู้ใช้ (ใช้รหัสผ่านเดิมได้), องค์กรและสมาชิก (`operator` → สมาชิก), อุปกรณ์ (ใช้รหัสลับเดิมได้), ชื่อและหน่วยของแต่ละช่อง,
กฎแจ้งเตือน (`> 8` กับ `< 2` รวมเป็นช่วงปกติ 2–8), ประวัติแจ้งเตือน, LINE/อีเมลของผู้ใช้ และข้อมูลย้อนหลังทั้งหมด

ไม่ย้าย: อุปกรณ์และองค์กรที่ปิดใช้งาน (ใส่ `--include-inactive` ถ้าต้องการ), กฎแบบ `==` / `!=`, แพ็กเกจ/โควตา
และ push token มือถือ ทุกข้อจะถูกระบุในรายงาน

| ตัวเลือก | ใช้เมื่อ |
|---|---|
| `--no-telemetry` | ย้ายเฉพาะผู้ใช้ อุปกรณ์ และการตั้งค่า |
| `--window-hours 6` | อุปกรณ์มีหลายช่องมาก และหน่วยความจำไม่พอ |
