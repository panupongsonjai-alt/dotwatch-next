# ย้ายข้อมูลจากระบบเก่า

สคริปต์ `npm run legacy:import` อ่านฐานข้อมูลระบบเก่า**อย่างเดียว** แล้วเขียนลงฐานระบบใหม่ รันซ้ำได้เสมอ
รอบหลังจะเพิ่มเฉพาะส่วนที่เปลี่ยน และถ้าหยุดกลางทางก็รันคำสั่งเดิมเพื่อทำต่อ

## สิ่งที่ย้าย

| ระบบเก่า | ระบบใหม่ |
|---|---|
| ผู้ใช้ (Firebase UID เดิม) | ผู้ใช้ + องค์กรส่วนตัว เข้าด้วยรหัสผ่านเดิม |
| องค์กรและสมาชิก (`operator` → สมาชิก) | องค์กรและสมาชิก |
| อุปกรณ์ (รหัสเดิม) | อุปกรณ์ในองค์กรเดิม หรือองค์กรส่วนตัวของเจ้าของ |
| รหัสลับอุปกรณ์ | ใช้รหัสเดิมได้ถ้ามี `LEGACY_SECRET_KEY` ไม่อย่างนั้นออกใหม่ลงไฟล์ CSV |
| ชื่อ หน่วย ลำดับ ทศนิยมของแต่ละช่อง | ตั้งค่าชื่อและหน่วยต่ออุปกรณ์ |
| กฎ `> 8` และ `< 2` ของค่าเดียวกัน | รวมเป็นช่วงปกติ 2–8 |
| ประวัติแจ้งเตือน | ประวัติ (อันที่ยังเปิดอยู่ถูกปิด ระบบใหม่จะเปิดใหม่เองถ้ายังผิดปกติ) |
| LINE / อีเมลของผู้ใช้ | ผู้รับแจ้งเตือนในองค์กรที่อุปกรณ์ของคนนั้นอยู่ |
| `device_metric_readings` + `sensor_readings` | `readings` (ค่าซ้ำจากการเขียน 2 ตารางรวมเป็นแถวเดียว) |

ไม่ย้าย: อุปกรณ์และองค์กรที่ถูกปิดใช้งาน, กฎแบบ `==` / `!=`, แพ็กเกจ/โควตา, push token มือถือ (ทำใหม่ในชุด 5),
อุปกรณ์สภาพอากาศเสมือนจะย้ายมาพร้อมข้อมูลเดิมแต่จะไม่มีค่าใหม่เข้ามา ทุกข้อจะถูกระบุในรายงาน

## เตรียม

ใส่ 2 บรรทัดนี้ใน `services\api\.env` (ห้าม commit และห้ามส่งให้ใคร):

```
LEGACY_DATABASE_URL=<DATABASE_URL ของ backend ระบบเก่าบน Render>
LEGACY_SECRET_KEY=<DEVICE_SECRET_ENCRYPTION_KEY ของระบบเก่า>
```

ทั้งสองค่าอยู่ใน Render → service backend ระบบเก่า → Environment

## ซ้อม (ทำ 2 รอบให้ผ่านติดกันก่อน cutover)

ปลายทางคือฐาน production ของระบบใหม่ (`dotwatch-prod` ที่ยังไม่มีผู้ใช้จริง) และต้องใช้ `DEVICE_SECRET_PEPPER`
**ค่าเดียวกับบน Render** ไม่อย่างนั้นรหัสลับที่ย้ายมาจะใช้กับ API จริงไม่ได้ ค่าที่ใส่ในหน้าต่าง PowerShell
จะใช้แทนค่าใน `.env` เฉพาะหน้าต่างนั้น:

```powershell
$env:DATABASE_URL="<connection string ของ dotwatch-prod>"
$env:DEVICE_SECRET_PEPPER="<DEVICE_SECRET_PEPPER จาก Render → dotwatch-api>"
npm run db:migrate
npm run legacy:import -- --dry-run
```

ดูตัวเลขและข้อควรรู้ที่พิมพ์ออกมา ถ้าโอเคให้ย้ายจริง:

```powershell
npm run legacy:import -- --yes
```

✅ บรรทัดท้ายต้องเป็น `ตรวจยอดแถว: ตรงกันครบ ✅` รายงานเต็มอยู่ใน `_reports\legacy-import-<เวลา>\report.md`

รอบที่ 2: รัน `npm run legacy:import -- --yes` ซ้ำ ต้องผ่านอีกครั้งและไม่มีอะไรซ้ำ

ปิดหน้าต่าง PowerShell เมื่อเสร็จ เพื่อไม่ให้คำสั่งถัดไปชี้ไป production โดยไม่ตั้งใจ

## ไฟล์ new-device-secrets.csv

อุปกรณ์ที่ระบบเก่าไม่มีรหัสลับแบบถอดได้จะได้รหัสใหม่ในไฟล์นี้ ใช้ตอนแฟลชบอร์ดวัน cutover
ไฟล์อยู่ใน `_reports\` ซึ่ง git ไม่เก็บ ห้ามส่งต่อหรืออัปโหลด

## ตัวเลือก

| ตัวเลือก | ใช้เมื่อ |
|---|---|
| `--dry-run` | ดูว่าจะย้ายอะไรบ้าง โดยไม่เขียนอะไร |
| `--yes` | ย้ายจริง (ต้องใส่ทุกครั้ง) |
| `--no-telemetry` | ย้ายเฉพาะผู้ใช้ อุปกรณ์ และการตั้งค่า |
| `--include-inactive` | ย้ายอุปกรณ์ที่ถูกปิดใช้งานด้วย |
| `--window-hours 6` | อุปกรณ์มีหลายช่องมาก และหน่วยความจำไม่พอ |
